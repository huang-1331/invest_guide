# A 작업 실행 규칙

- 기준: docs/ROADMAP.md의 3일 MVP. A는 사용자, B의 실명은 미확정.
- 실제 앱: 이 Git 저장소 루트(현재 로컬 위치 sites/jusik-guide/). 이하 경로는 저장소 루트 기준. 바깥 exports/는 인계본이므로 직접 개발 대상에서 제외.
- 코드 위치가 달라진 환경에서는 임의로 선택하지 말고 사용자에게 확인.
- 이 문서·로드맵·docs/WORK_PROGRESS.json·적용되는 AGENTS.md를 작업 시작 시 확인.

## 작업 분량 판단

- 한 번에 독립적으로 완료·검토할 목표 1개, 주요 코드 파일 1~3개.
- 파일 수보다 영향 범위·외부 의존성·검증 난이도를 우선. 압축된 app.js의 줄 수는 분량 기준이 아님.
- 한 작업에 전체 리팩터링·데이터 수집·화면 구현·배포를 묶지 않음.
- 목표가 커지면 범위·분할안을 기록하고 사용자에게 선택 요청. 다음 작업 자동 착수 금지.
- 이미 충족한 목표는 재구현하지 않고 검증 근거를 남김.
- 3일은 프로젝트 일정이지 AI 호출 실행시간 보장이 아님. 승인·B 인계 대기는 별도 의존성.

## 모든 프롬프트에 적용할 4단계

1. Understand: 현재 코드와 진행 기록을 읽고 구체적 달성 목표·선행 조건·완료 기준 확인.
2. Plan: 최소 수정 범위·접근법·검증 방법 수립. 긴 사고 과정 대신 짧은 실행 근거만 제시.
3. Execute: 현재 작업만 직접 수행. A 소유 파일 중심으로 변경하고 사용자 수정 보존.
4. Review: 계획과 실제 결과·문제·검증 근거 비교. 근거가 없는 완료 판정 금지.

## 모호성·권한

- 의미·목표·요구·정답·데이터 계약·저장 정책·대상 환경이 모호하면 추측 금지.
- 구현을 즉시 중단하고 blocked를 기록한 뒤 구체적 질문과 2~3개 선택지 제시.
- 응답 전 해당 작업 재개 금지. 시간 경과·무응답을 승인으로 간주하지 않음.
- B 인계가 없으면 B 파일을 대신 작성하거나 스키마를 발명하지 않음.
- B 소유: dist/data.js, API_CONTRACT.md, CONTENT_REVIEW.md. 계약 변경은 공동 합의 필요.
- 프레임워크 전환·서버/DB·실제 분석·추가 기능은 범위 밖.
- 배포 전 작업은 로컬 검증까지. A-T07에서만 배포. 기존 Sites ID·공개 범위 유지.
- 공유 범위 확대·협업자 추가가 필요하면 대상과 권한을 확인한 뒤 진행.

## 공용 진행 JSON

- 정본: 이 Git 저장소 안 docs/WORK_PROGRESS.json. 코드와 함께 버전 관리하며 바깥 docs/ 사본은 사용하지 않음.
- 상태: pending, in_progress, blocked, done.
- 시작 전 최신 파일 읽기. 종료·오류·중단 때마다 현재 작업 기록 갱신.
- 기록: status, objective, changes, checks, issues, additional_requirements, next_task, updated_at.
- checks: 항목·passed/failed/not_run·실제 근거. 검사 미수행은 통과로 기록하지 않음.
- issues: 문제·영향·해결 필요 사항. additional_requirements: 새 요구 및 미확정 결정.
- 완료: 필수 완료 기준과 검증 충족 시에만 done. 막힘은 blocked·이유·질문·선택지 기록.
- 기존 B 기록·다른 작업·사용자 결정을 보존. 전체 파일을 초기화하지 않음.
- revision을 확인하고 저장 직전 재확인. 변경되었으면 최신 내용을 다시 읽고 현재 작업만 병합.
- 실제 공동 쓰기는 한 명씩 직렬화. 다른 작성자가 편집 중이면 쓰기 중단·조율.
- 임시 파일 작성 → JSON 파싱 검사 → 원본 교체. 저장 성공 후 revision 증가 확인.
- 원격 동기화가 없으면 이 파일은 로컬 기록임을 명시. 공유 저장소 또는 버전 표시 인계본으로 전달 후 다음 작성자 진행.
- 작업 종료 때 코드 버전/해시 또는 파일 검증 근거와 다음 담당자가 필요한 인계 사항을 함께 기록.
- 키·토큰·개인정보는 기록하지 않음.

- 한국어·짧은 개조식. 정상 종료 시 완료/검증/미해결/다음 작업 최대 4개 항목.
- 모호성 발생 시 질문 1개와 선택지 2~3개 중심. 내부 사고 과정 장문 출력 금지.
- 작업 프롬프트가 요구하는 구현·검토·진행 기록은 최소 출력 원칙 때문에 생략하지 않음.
